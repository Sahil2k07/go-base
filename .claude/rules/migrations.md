# Migrations

- Folder = object type: `tables`, `indexes`, `views`, `functions`, `procedures`, `triggers`. The runner applies them in that order, files inside a folder by filename.
- Name files `NNN_description.sql`: lowercase snake*case, starting with a zero-padded number (`001*`, `002\_`, continuing), e.g. `007_create_role_permission.sql`, `003_idx_user_sessions_user_id.sql`. No uppercase, hyphens or spaces.
- The runner sorts file names and applies them in that order (like goose), so the number is the execution order. Zero-padding keeps the sort correct; numbers are per folder, never reused or renumbered. A table's number must be lower than any table that references it.
- The runner skips applied files by name. Never edit an applied file; add a new one (`ALTER TABLE ... ADD COLUMN IF NOT EXISTS`).
- Every statement must be safe to run twice: `CREATE TABLE/INDEX IF NOT EXISTS`, `CREATE OR REPLACE` for views/functions/procedures, `DROP TRIGGER IF EXISTS` before `CREATE TRIGGER`.
- Table layout: columns first, blank line, then named constraints (`pk_`, `fk_`, `uq_`). Indexes are named `idx_` / `uq_`.
- Types: `BIGINT GENERATED BY DEFAULT AS IDENTITY` keys, `TIMESTAMPTZ`, `VARCHAR(n)` matching the model's `size:`, `UUID` for `uuid.UUID`.
- `gorm.Model` tables need `created_at`, `updated_at`, `deleted_at` plus an index on `deleted_at`. Unique columns on them need a partial index:
  `CREATE UNIQUE INDEX IF NOT EXISTS uq_users_email ON users (email) WHERE deleted_at IS NULL;`
- Join tables: no `gorm.Model`, composite primary key, index on the second column, `ON DELETE CASCADE` on both foreign keys.
- The SQL is the source of truth. Keep the model's gorm tags in sync with it.
